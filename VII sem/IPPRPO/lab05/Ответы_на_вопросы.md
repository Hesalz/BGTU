## Контрольные вопросы

**1. Что такое Static Analysis?**  
Static Analysis (статический анализ) — автоматизированная проверка исходного кода без запуска приложения. Она позволяет находить нарушения правил оформления и другие потенциальные проблемы непосредственно в коде.

**2. Чем Static Analysis отличается от тестирования?**  
Static Analysis проверяет исходный код и его соответствие заданным правилам, не запуская приложение. Тестирование запускает программу или отдельные её части и проверяет правильность их поведения. Эти подходы дополняют друг друга.

**3. Что такое Checkstyle?**  
Checkstyle — инструмент статического анализа Java-кода, который проверяет его соответствие заданным правилам оформления и организации, например длину строк, именование и использование конструкций языка.

**4. Что такое Code Style?**  
Code Style — набор правил оформления и организации исходного кода. Он определяет единый подход к именованию, отступам, длине строк и другим элементам, благодаря чему код проще читать и сопровождать.

**5. Что такое нарушение правила статического анализа?**  
Это несоответствие исходного кода одному из правил, заданных в конфигурации анализатора. Например, строка может превышать установленную максимальную длину или имя переменной может не соответствовать принятому соглашению.

**6. Может ли Static Analysis выполняться без запуска приложения?**  
Да. Статический анализ исследует исходный код и его структуру, поэтому для его выполнения не требуется запускать приложение. В данном проекте проверка запускается командой `mvn checkstyle:check`.

**7. Что происходит при обнаружении нарушения правила?**  
Checkstyle указывает файл, строку и правило, которое было нарушено. В настройках данного проекта обнаруженное нарушение приводит к ненулевому коду завершения Maven, поэтому этап Static Analysis в Jenkins завершается с ошибкой и последующие этапы Pipeline пропускаются.

**8. Что такое Logging?**  
Logging (журналирование) — запись информации о событиях, происходящих во время выполнения приложения. Журнал помогает понять последовательность операций, обнаруживать ошибки и анализировать поведение программы.

**9. Почему System.out.println() не является полноценной заменой Logging?**  
`System.out.println()` просто выводит текст и не предоставляет полноценного управления уровнями важности, настройками формата и направления вывода. Logging позволяет централизованно настраивать сообщения и разделять обычные события, предупреждения и ошибки.

**10. Что такое Logger?**  
Logger — объект, через который приложение создаёт сообщения журнала. Он позволяет записывать события с разными уровнями важности и указывать класс, из которого поступило сообщение.

**11. Что такое Log Level?**  
Log Level — уровень важности сообщения журнала. В данной лабораторной работе используются уровни INFO, WARN и ERROR.

**12. Для чего используется уровень INFO?**  
INFO используется для записи обычных значимых событий приложения, например начала операции покупки билета или успешной продажи билета.

**13. Для чего используется уровень WARN?**  
WARN используется для предупреждений о проблемных ситуациях, которые не обязательно являются критическими ошибками. В проекте этот уровень применяется при попытке купить уже занятое или недоступное место.

**14. Для чего используется уровень ERROR?**  
ERROR используется для регистрации возникшей ошибки, которая помешала выполнить операцию. В проекте он применяется, если при сохранении билета в репозитории или занятии места возникает исключение.

**15. Что такое SLF4J?**  
SLF4J (Simple Logging Facade for Java) — фасад, предоставляющий единый интерфейс для журналирования в Java-приложениях. Код приложения обращается к Logger через SLF4J и не зависит напрямую от конкретной реализации журналирования.

**16. Что такое Logback?**  
Logback — библиотека, реализующая журналирование для Java. Она принимает сообщения, переданные через SLF4J, и определяет, как и куда их выводить.

**17. Как связаны SLF4J и Logback?**  
SLF4J предоставляет интерфейс Logger, а Logback является реализацией, которая обрабатывает сообщения. В проекте приложение вызывает методы SLF4J, а Logback выводит сформированные сообщения в консоль согласно настройкам `logback.xml`.

**18. На каком этапе Pipeline выполняется Static Analysis?**  
Static Analysis выполняется на отдельном этапе `Static Analysis`, который расположен после `Build` и перед `Test`.

**19. Что произойдет, если Static Analysis завершится с ошибкой?**  
Этап Static Analysis получит статус FAILURE. Jenkins остановит дальнейшее выполнение последовательности, поэтому этапы Test и Package будут пропущены. После исправления нарушения и отправки изменений в Git Pipeline можно запустить повторно.

**20. Чем результат Static Analysis отличается от результата Logging?**  
Результат Static Analysis — отчёт о проверке исходного кода с перечнем найденных нарушений или подтверждением успешной проверки. Результат Logging — журнал событий, которые произошли во время выполнения приложения.

**21. В чем состоит роль Static Analysis в Continuous Integration?**  
Static Analysis автоматически проверяет качество исходного кода при интеграции изменений. Включение проверки в Jenkins Pipeline позволяет обнаруживать нарушения на раннем этапе и не допускать перехода к тестированию и упаковке проекта, если проверка не пройдена.
