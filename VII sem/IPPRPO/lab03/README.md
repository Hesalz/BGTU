# ЛР №3 — Кинотеатр, вариант 2

## Pipeline
В корне проекта находится `Jenkinsfile`. Этапы выполняются последовательно:

1. **Build** — `mvn compile`: компиляция основного Java-кода.
2. **Test** — `mvn test`: запуск JUnit-тестов.
3. **Verify** — `mvn validate`: дополнительная предварительная проверка корректности Maven-проекта и доступности его конфигурации до упаковки. Это индивидуальное задание варианта 2.
4. **Package** — `mvn package -DskipTests`: создание JAR после успешных предыдущих этапов. Тесты здесь пропускаются, потому что отдельный этап Test уже запустил их.

Использован синтаксис `bat`, поскольку инструкция рассчитана на Jenkins, работающий в Windows.

## Запуск на Windows
1. Установите JDK 21, Maven и Jenkins; проверьте в командной строке `java -version` и `mvn -version`.
2. Создайте в Jenkins задачу **New Item → Pipeline**, например `Lab3-Cinema`.
3. Скопируйте содержимое проекта (файлы `pom.xml`, `Jenkinsfile`, `src`) в папку workspace этой задачи так, чтобы `pom.xml` лежал непосредственно в корне workspace.
4. В настройке Pipeline выберите **Pipeline script from SCM**, если проект подключён к SCM, либо временно вставьте содержимое `Jenkinsfile` в **Pipeline script**. Для второго варианта Jenkins всё равно должен видеть `pom.xml` и `src` в workspace. Если используете встроенный Pipeline script, не забывайте синхронизировать его с файлом `Jenkinsfile`.
5. Нажмите **Build Now**, затем откройте **Console Output** и проверьте порядок этапов и `Finished: SUCCESS`.
6. После успешной сборки JAR ищите в `target/` (имя обычно `lab02-1.0.jar`); Maven также создаёт `target/plugin-result.txt` на фазе `verify` при вызове этой фазы. Текущий Pipeline вызывает `validate`, а затем `package`, поэтому привязанный к фазе `verify` Ant-плагин не запускается. Это существующее индивидуальное задание ЛР №2 и не является этапом Verify ЛР №3.

## Проверка обработки ошибки тестов
Для демонстрации временно измените ожидаемое значение в одном из тестов `CinemaTest.java`, например ожидаемое количество свободных мест, чтобы тест падал. Запустите Pipeline: Build завершится успешно, Test завершится ошибкой, а Verify и Package не выполнятся. Затем обязательно восстановите исходное значение теста и запустите Pipeline ещё раз. Не сдавайте проект с намеренно сломанным тестом.

## Индивидуальное задание — вариант 2
Добавлен этап `Verify` между `Test` и `Package`. Он запускает `mvn validate`, которая проверяет корректность проекта и его Maven-конфигурации на ранней стадии жизненного цикла. Если команда завершится с ненулевым кодом, Jenkins пометит Pipeline как неуспешный и не запустит Package. Результат проверяется по статусу этапа и строкам команды в Console Output.

Примечание: `mvn validate` — базовая проверка Maven-проекта, а не статический анализ бизнес-логики. Она выбрана потому, что дополнительная проверка должна завершиться до этапа упаковки и не дублировать `mvn test` или заранее запускать фазу `package`.
