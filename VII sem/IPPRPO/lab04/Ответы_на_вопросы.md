## Контрольные вопросы

**1. Что такое Git?**  
Git — распределённая система контроля версий, позволяющая хранить историю изменений проекта.

**2. Для чего используется система контроля версий?**  
Для отслеживания изменений, сохранения истории и совместной разработки.

**3. Что такое Git Repository?**  
Git Repository — репозиторий, в котором хранятся файлы проекта и история их изменений.

**4. Чем Local Repository отличается от Remote Repository?**  
Local Repository находится на компьютере разработчика, Remote Repository — на удалённом сервере.

**5. Что такое Working Directory?**  
Рабочая директория — каталог с файлами проекта, которые разработчик редактирует.

**6. Что такое commit?**  
Commit — зафиксированное состояние проекта с описанием изменений.

**7. Что делает git add?**  
Добавляет изменения в индекс для последующего коммита.

**8. Чем git commit отличается от git push?**  
`git commit` сохраняет изменения в локальном репозитории, а `git push` отправляет коммиты в удалённый.

**9. Что делает git status?**  
Показывает состояние рабочей директории и индекса.

**10. Для чего используется git log?**  
Для просмотра истории коммитов.

**11. Для чего используется git remote?**  
Для просмотра и настройки связей с удалёнными репозиториями.

**12. Что такое origin?**  
`origin` — стандартное имя удалённого репозитория, добавленного в Git.

**13. Для чего нужен .gitignore?**  
Для указания файлов и каталогов, которые Git не должен отслеживать.

**14. Почему каталог target обычно не хранится в Git?**  
Он содержит результаты сборки Maven, которые можно создать повторно.

**15. Какие файлы необходимо хранить в Git для Maven-проекта?**  
Исходный код, тесты, `pom.xml`, `Jenkinsfile` и другие необходимые файлы проекта.

**16. Что такое SCM?**  
SCM (Source Code Management) — управление исходным кодом и его версиями.

**17. Что такое checkout?**  
Checkout в Jenkins — получение исходного кода из репозитория в рабочую директорию сборки.

**18. Что такое Pipeline script from SCM?**  
Режим Jenkins, в котором сценарий Pipeline загружается из системы контроля версий.

**19. Почему Jenkinsfile удобно хранить в Git?**  
Он версионируется вместе с проектом, поэтому изменения Pipeline можно отслеживать и восстанавливать.

**20. Чем Jenkinsfile отличается от pom.xml?**  
`Jenkinsfile` описывает этапы автоматической сборки, а `pom.xml` — настройки Maven-проекта и его зависимости.

**21. Для чего используется Poll SCM?**  
Для периодической проверки репозитория на новые изменения и автоматического запуска сборки при их обнаружении.

**22. Что произойдет, если Jenkins не сможет получить проект из Git?**  
Этап Checkout завершится ошибкой, и Pipeline не сможет продолжить сборку.

**23. Что произойдет, если mvn test завершится с ошибкой?**  
Этап тестирования завершится неуспешно. Последующие этапы, например Package, будут пропущены, если Pipeline настроен на остановку при ошибке.

**24. Почему Jenkins не заменяет Git?**  
Git хранит историю изменений и управляет версиями кода, а Jenkins автоматизирует сборку и тестирование.

**25. Почему Jenkins не заменяет Maven?**  
Maven управляет зависимостями, компиляцией и тестированием Java-проекта, а Jenkins запускает эти операции в рамках Pipeline.

**26. В чем состоит основная идея Continuous Integration?**  
В регулярном объединении изменений кода с автоматической сборкой и тестированием для раннего обнаружения ошибок.
